## Generating art with PixelLab

`game/tools/pixellab_client.py` (used by the Asset Generation Agent) calls the PixelLab API (https://api.pixellab.ai/v2) directly, with Python 3.9+ and the standard library only. It reads `PIXELLAB_API_KEY` from the environment or from `.env` (see [Secrets and API keys](../../../README.md#secrets-and-api-keys)) and never prints or stores it. Run it from the repo root.

**Balance (free):**

```
python game/tools/pixellab_client.py balance
```

**Generate one asset (a paid call), only inside the style loop:**

`generate` runs only inside a live style loop run (T-292; `tasks/README.md`, "The style loop", "How it is enforced"). The Asset Generation Agent calls it from the session `python tools/style_loop/run.py art ...` starts, which inherits the run's marker through the `SOLID_CARBIDE_STYLE_LOOP_RUN` environment variable. Run anywhere else, or after the run has ended, it is refused with exit code 1 and a message naming `tools/style_loop/run.py`, before the token is read or anything is sent to PixelLab. `balance` works anywhere.

```
python game/tools/pixellab_client.py generate --endpoint create-image-pixflux \
  --params '{"description": "...", "image_size": {"width": 64, "height": 64}}' \
  --out-dir game/art/<folder> --name <asset-name> \
  --consulted docs/visual-style.md --consulted <other resource> --task T-000
```

- `--endpoint` takes the endpoint without its leading slash (Git Bash turns a leading `/` into a Windows path). Known endpoints: `create-image-pixflux`, `create-image-bitforge`, `inpaint` and `rotate` (direct: the image comes back in the response; `rotate` takes no prompt), `create-isometric-tile` (asynchronous: the script polls the background job every 5 s, stops with an error on `failed` or after 10 minutes, then fetches the tile) and `generate-8-rotations-v3` (asynchronous, polled for up to 20 minutes; it returns 8 images, each saved as `<name>_<index>.png` with its own record, and each record says the call's usage is shared by all of them). Others are added in the `ENDPOINTS` table at the top of the script. The HTTP read timeout is 600 s: slow calls are charged even when they time out.
- `--params` is the request body as JSON; `--params-file` reads it from a file instead. `--consulted` (repeatable, at least one) lists the documents and other resources looked at before generating. `--notes` adds free text to the record.
- Each call makes exactly one generation request and never retries. It refuses to overwrite an existing `<name>.png` or `<name>.json`, so an asset cannot be regenerated by accident.
- It saves `<name>.png` and a record `<name>.json` next to it: `endpoint`, `request_params`, `prompt`, `job_id` (`null` for direct endpoints), any result id such as `tile_id`, `usage` (the cost PixelLab reports), `generated_at`, `image` (width, height), `resources_consulted`, `task` and `notes`.
- Every generation call, successful or not, is also appended to `game/art/pixellab-generation-log.jsonl`, with the style loop run it was made in (`style_loop_run`).
- Exit codes: 0 = saved (or balance shown); 1 = not inside a style loop run, token missing, bad parameters, request failed, job failed or polling timed out; 2 = bad command-line arguments.

**The style rules (T-290):** `game/tools/style_rules.py` is the one place the style guide's script checks live (Visual style, Content, "Rules" and Extended narrative, Content, "Text rules", the rules marked *(script)*); the style loop runs it first (`tasks/README.md`, "The style loop"). `python game/tools/style_rules.py art <png> [--size WxH] [--frames N] [--greenbull] [--allow-colour R,G,B] [--max-colors N]` checks Visual style rule 1 (alpha 0 or 255 only, transparent corners, at most 30 colours), rule 3 (the size of the image, or of each frame of a one-row sheet with `--frames`) and rule 6, Greenbull's colours (T-298): no colour that reads as Greenbull's light green (104, 220, 96) or yellow (247, 208, 52), closer than `GREENBULL_MAX_DIST` (25 in 0..255 RGB distance, so the city's amber and the fire oranges stay clear), unless `--greenbull` marks one of Greenbull's own things (its logo, the gift pack and its helicopter, the weapons, the level-up screen) or `--allow-colour` names a colour allowed on this asset all the same (a fire's yellow; `--allow-red` is its old name and still works). Red is not reserved: no sprite fails rule 6 for red. The dark green (12, 76, 44) is not checked, as it is also the car's colour. `--logo` runs Greenbull's logo check instead (`check_logo`; the approved emblem `art-archive/T-294/greenbull_emblem_128.png`, `_64`, `_32` and wordmark `art-archive/T-295/greenbull_wordmark.png` pass): the logo is flat brand art, exempt from rule 2 but bound by rule 1, so it checks rule 1 only. `python game/tools/style_rules.py text "<text>" --kind popup|card_title|card_desc|garage_name|garage_desc|label` checks text rule 2 (no "XP", "points", "Godzilla" or the sponsor's old name, in any case), rule 3 (no "Greenbull says ...") and rule 4 (popups in capitals ending in "!", card title 30 and description 90 characters, garage name 25 and description 80 with no digits, labels in sentence case, "Greenbull" among the names a label may capitalise). Each prints a JSON list of checks, each with its `rule` number, `check`, `ok` and `detail`, and exits 1 when any fails. The build scripts import its PNG reader, sprite checks, Greenbull's colours (`GREENBULL_*`, `greenbull_colour`) and the red-distance helpers the code-drawn colours still use (`OLD_LOGO_RED`, `HEART_COLOR`, `reads_as_red`; renamed by T-306, values and checks unchanged) instead of keeping their own. `check_sprite_rules.py` is a thin wrapper for the old sprite command (rules 1 and 3; `--rule6` adds rule 6), and `python game/tools/check_sprite_rules.py --rule6-report game/art [--against master]` prints rule 6 for every PNG under a folder, next to the result of `style_rules.py` at a git revision. `check_greenbull_logo.py <png> ...` runs Greenbull's logo check; `check_logo_one_colour.py` is kept as the old logo's one-colour check (`check_old_logo`, T-075), history only. Tests: `game/tools/test_style_rules.py`, `test_check_sprite_rules.py`, `test_check_greenbull_logo.py`, `test_check_logo_one_colour.py`.

**Palette and previews (free, no PixelLab call):** `python game/tools/reduce_palette.py reduce IN.png OUT.png [--max-colors 30]` merges a sprite's least-used colours into the nearest remaining ones until at most 30 are left (no new colours, alpha unchanged); `python game/tools/reduce_palette.py preview IN.png OUT.png [--scale 4]` enlarges it (nearest-neighbour) on a dark and a light background side by side. Tests: `game/tools/test_reduce_palette.py`.

**Boulder base removal (T-065, free):** `python game/tools/remove_boulder_base.py build` removes the stone disc under the first sample boulder (`art-archive/T-065/boulder_sample.png`), keeps the rock pixel-identical above the disc, closes its bottom with the sprite's own outline colour and writes `boulder_sample_nobase.png`, its record and three previews to `art-archive/T-065/`; `check` confirms the committed sprite matches a fresh build. Tests: `game/tools/test_remove_boulder_base.py`.

**Boulder art (T-065, free):** `python game/tools/build_boulder_art.py build` makes the game-ready boulders in `game/art/boulders/` from the two samples the board approved (see "The boulders (T-065)" below); `check` confirms the committed files match a fresh build; `--no-mirrors` leaves out the mirrored copies. Tests: `game/tools/test_build_boulder_art.py`.

Its Python tests (`game/tools/test_pixellab_client.py`) run with the Python tool tests command above and never call PixelLab. `game/tests/unit/test_pixellab_assets.gd`, part of the GUT suite, checks that every generated PNG under `art/` loads in Godot with the size its record gives.
