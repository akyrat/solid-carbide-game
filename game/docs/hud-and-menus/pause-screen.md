## Pause screen

Task T-015 (UI Agent). Escape (the `pause` action in the input map) pauses the whole game tree and shows the pause screen: the title, a hint that Escape resumes, and one setting, the camera zoom slider (6 to 20, default 14.4, the same value as the tuning panel's zoom slider; moving either updates the other). Pressing Escape again resumes from exactly where the car was. The tuning panel (Tab) does not work while paused. The texts are from task T-047. The slider's label is "Camera zoom level" (T-093). The panel sits in a compact strip just below the HUD timer (`STRIP_TOP`), only as tall as its content (T-095), over a light dim, and moving the slider zooms the view behind it at once while everything stays paused (the camera normally updates in the physics step, which does not run while paused, so while paused it updates every frame with physics interpolation off, and resuming puts it back). A full pause menu with more settings is task T-016.

- `scripts/ui/pause_screen.gd`: the screen. It keeps processing while the tree is paused, handles Escape and sets the zoom on the scene it belongs to.
- `scripts/ui/game_settings.gd` (`GameSettings`): the saved zoom, in `user://settings.cfg` (section `camera`, key `zoom`), and since T-123 the camera options (see "Camera options"). Read when the game starts; no file, a bad value or no value gives 14.4, and a saved value outside 6 to 20 is clamped. The pause sliders save on release and on close (see "Sliders save on release" below); the tuning panel's zoom slider and its reset button do not save.
- **HUD size slider label (task T-426):** the text is "HUD size", in `data/pause_text.json` under `hud_size_label` (no value text: the number at the right end is bare, like the other sliders). Since T-431 the pause screen reads it (`hud_size_text()`, `PAUSE_TEXT_FILE`, `HUD_SIZE_LABEL_KEY`); no script spells the text out.
- **HUD size slider (task T-431):** `_build_hud_size_slider()` adds `HudSizeRow` directly under the music row, laid out like it: `hud_size_label` (width `LABEL_WIDTH`), `hud_size_slider` (expand-fill, no focus) and a right-aligned bare number. Range `GameSettings.MIN_HUD_SIZE` 50 to `MAX_HUD_SIZE` 125, step `HUD_SIZE_STEP` 5, default `DEFAULT_HUD_SIZE` 100 (percent; proposals for the playtest). `value_changed` calls the target's `hud.set_hud_size(v)` at once, paused or not (`_hud()` is null when the target has no HUD, as in the drift prototype: then the slider only saves). It saves with T-427's rule (key `hud_size`): on `drag_ended` and in `save_pending()` when the screen closes, through `GameSettings.save_hud_size()` (section `hud`, key `size`, clamped, counted in `slider_writes`). `pause()` sets the slider from the HUD's current `hud_size`. At the next start `GameFlow.add_run()` applies `GameSettings.load_hud_size()` to the run's HUD, before the pause screen is built. The slider sizes the run's HUD only (`hud.md`, "The HUD scales with the window"), not the pause screen, the level-up, time's up or recap screens, the menus, or the trick popups and the kaiju's bar (they are in the world). Tests: `tests/unit/test_hud_size_slider.gd`.
- **HUD layout editor (task T-453):** `_build_hud_layout_button()` adds `hud_layout_button` to `RunButtonsRow` after the Trick list button (a row of its own made the strip end below half the screen, `test_screen_flow.gd`) (the shared small button, text `hud_layout_button` from `data/pause_text.json` via `pause_text(key)`); `_build_hud_layout_editor()` adds `hud_layout_editor` (`scripts/ui/hud_layout_editor.gd`, `HudLayoutEditor`) to the screen's root. Both only when the target has a HUD (`_hud()`). `open_hud_layout()` hides `strip` and `_dim` and opens the editor; the editor's `done` signal (Done, Escape through `_input`, or `resume()`) calls `_on_hud_layout_done()`, which saves `hud.layout` once with `GameSettings.save_hud_layout()` (section `hud_layout`; counted in `GameSettings.hud_layout_writes`) and shows the strip again. The editor only collects drags (`press`, `drag_to`, `release`, the mouse in `_gui_input`) and passes them to `Hud.move_piece()`; Reset calls `Hud.reset_layout()`. At the next start `GameFlow.add_run()` applies `GameSettings.load_hud_layout()` with `hud.set_layout()`. Tests: `tests/unit/hud/test_hud_layout_editor.gd`. Screenshots: `bash game/tools/screenshot.sh res://tests/fixtures/t453_editor.tscn out.png 90` (and `t453_run*.tscn`), saved by the fixture in `art-archive/T-453/screenshots/`.
- **Camera controls (task T-124):** under the slider, `smoothing_check` ("Camera smoothing") and `dynamic_check` ("Dynamic camera"), and while the dynamic camera is on a `tuning_row` with `set_min_button` ("Set min zoom"), `min_label`, `set_max_button` ("Set max zoom") and `max_label`. They call `target.camera_follow` (see "Camera options") and read their state from it on pausing and on its `changed` signal. The two buttons are a temporary tool for the board and go once the values are settled. Tests: `tests/unit/test_pause_camera_controls.gd`. The checkboxes have their own placeholder icons (`check_icon()`: a light frame on a dark fill, a light square inside when checked) and the buttons their own frames (`button_style()`, for normal, hover, pressed and focus), and the strip is nearly opaque (`STRIP_COLOR`), so all of them show over the bright ground of a run (QA round 1). Screenshots with the dynamic camera on: in the drift prototype, `bash game/tools/screenshot.sh res://tests/fixtures/pause_screen_demo_dynamic.tscn screenshots/pause_dynamic.png 300`; in a run started from the main menu, `res://tests/fixtures/pause_run_dynamic_gravel.tscn` (the run's start, on the gravel) or `..._asphalt.tscn` (on the road), 60 frames. The run fixtures use their own test settings file (dynamic camera on, smoothing off, min 10.0 and max 17.5), never the player's real settings.
- **Restart and Exit (task T-327):** `restart_button` ("Restart") and `exit_button` ("Exit") in `RunButtonsRow`, the last row of the strip. They only emit `restart_pressed` and `exit_pressed`; the run's owner (`GameFlow`, or the level creator) banks the coins and swaps the screen (see `game/docs/game-loop/screen-flow.md`). Pausing puts the keyboard focus on Restart. No confirm prompt. Tests: `tests/unit/game/test_pause_restart_exit.gd`. Screenshot: `bash game/tools/screenshot.sh res://tests/fixtures/pause_from_menu_demo.tscn out.png 80`.
- **Trick list button and panel (task T-386):** `trick_list_button` ("Trick list", text from `data/tutorial_text.json` via `TrickList.text("button.trick_list")`) is the first button of `RunButtonsRow`. `open_trick_list()` hides `strip` and shows `trick_panel` (`TrickListPanel`, a `PanelContainer` in the strip's look, centred at the top, starting at `STRIP_TOP`), which holds `trick_list` (an instance of `scenes/menu/trick_list.tscn`, the seven tricks only, names at font size 18) and `trick_back_button` ("Back", `button.back`). `close_trick_list()` shows the strip again; none of its controls is touched. `is_trick_list_open()` tells which is showing. The tree stays paused throughout. **Escape** while the panel is open calls `close_trick_list()` instead of resuming (a second Escape resumes); `resume()` also closes the panel. Focus: Back on opening, the Trick list button on closing. Tests: `tests/unit/test_pause_trick_list.gd` (the panel is measured with the window forced to 1152 x 648, since the headless window is tiny). Screenshots: `bash game/tools/screenshot.sh res://tests/fixtures/pause_from_menu_demo.tscn out.png 80` (the pause screen with the button) and `res://tests/fixtures/pause_trick_list_demo.tscn` (the open panel); saved in `art-archive/T-386/screenshots/`.
- **SFX row hidden for the MVP (task T-389):** the sound effects are off (`GameSettings.sfx_enabled()`, the `sfx_enabled` switch in `data/sfx.json`, T-388), so `_build_sfx_slider()` still builds the row (`SfxRow`, `sfx_slider`, `sfx_label`) but sets `row.visible = GameSettings.sfx_enabled()`. A hidden row takes no room in the strip's `VBoxContainer`, so the music row and everything under it move up. The music slider is unchanged. Turn the switch on and the row shows again. Tests: `test_sfx_row_hidden_with_the_switch_off_and_layout_closes_up` in `tests/unit/test_pause_screen.gd`; the tests of the row itself (`test_sfx_volume.gd`, `test_music_volume_slider.gd`, two in `test_screen_flow.gd`) set `GameSettings.sfx_enabled_override = 1`. Screenshot: `art-archive/T-389/screenshots/`.
- **Sliders save on release and on close (task T-427):** the zoom, SFX volume and music volume sliders apply live in `value_changed` (`set_zoom`, `apply_sfx_volume`, `apply_music_volume`) and only mark themselves changed (`_dirty`). They save when the drag ends (`_wire_save_on_release()`: `drag_ended` with `value_changed` true) and `save_pending()` saves whatever is still changed when the screen closes: `resume()` (Escape), the Restart button and the Exit button call it first. A drag of 20 values is one write; a keyboard or click change is written on close. The HUD size slider must use `_wire_save_on_release()`, `_mark_dirty()` and a case in `_save_slider()`. `GameSettings.slider_writes` counts writes of these three settings, for the tests. Tests: `tests/unit/test_pause_slider_saves.gd`.
