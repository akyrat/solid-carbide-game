## Level-up screen

T-310: the ribbon's `TitleLabel` is lettered in cream (`TITLE_CREAM`, RGB 246, 250, 232) with a dark outline (`TITLE_OUTLINE`, RGB 14, 22, 18, `TITLE_OUTLINE_SIZE` 4) so it reads on a dark green ribbon; card titles, descriptions and buttons keep black ink (`INK`).

Task T-052 (UI Agent). What the player sees and does: `docs/hud-and-menus.md`, "Level-up screen". `scripts/ui/level_up_screen.gd` (`LevelUpScreen`, a CanvasLayer at layer 15: over the HUD, under the pause screen) is a child of the run (`run.level_up_screen`, node `LevelUpScreen`), set up with the weapon rack. Since T-144 a level-up no longer opens it by itself: the car drives over the gift pack's package (see "The gift pack drop"), which calls `state.open_choice(level)` and pauses the tree (`run.gd` keeps `state.pause_on_level_up` off); the screen listens to `run.weapons.offers.offers_ready`, shows a card per id and calls `offers.choose(id)` for the one taken; it closes on `offer_taken` and on a new run. It keeps processing while the tree is paused.

- `cards`: one `{id, panel, body, highlight_frame, image, title, desc, click}` per offered id; `highlight` is the highlighted index. `card_text(id)` gives `{title, desc}`: every `upgrade_<weapon>` id uses that weapon's tier now + 1 (`upgrade_gun.tier4.*` for a gun at tier 3, `upgrade_wiper.tier5.*` for a wiper at tier 4; T-173 made this work for all five weapons through `rack.get_weapon(offers.weapon_of(id))`).
- Weapon image (T-173): each card's `WeaponImage` (`TextureRect`, 64 x 64, `STRETCH_KEEP_ASPECT_CENTERED`, nearest filtering) sits above the title in the card's `VBoxContainer`. `LevelUpScreen.weapon_image(weapon_id)` loads `res://art/level_up/weapon_<weapon id>.png` (`WEAPON_ART`; ids `gun`, `flamethrower`, `underglow`, `molotov`, `wiper`) when it exists, otherwise `placeholder_image(weapon_id)`: a 16 x 16 `ImageTexture` built (and cached) from `PLACEHOLDER_GRIDS` (one character per pixel, `.` transparent) and `PLACEHOLDER_COLORS` (opaque, clear of the heart's red). The art task (T-174) added the five PNGs under those names in `art/level_up/` (`weapon_gun.png`, `weapon_flamethrower.png`, `weapon_underglow.png`, `weapon_molotov.png`, `weapon_wiper.png`, 64 x 64, PixelLab, each with its record JSON; requests and the raw molotov in `art-archive/T-174/`), so the placeholders now only show for an id without a file; `test_final_weapon_art_replaces_the_placeholders` checks size, hard edges and transparent background. `CARD_SIZE` is 360 x 374 (74 px taller than T-141's for the image and its gap); the `HighlightFrame` is now a `NinePatchRect` (margin 10) of `highlight_frame.png` so it keeps its 6-art-pixel border on the taller card. `take(id)`, `take_highlighted()`, `move_highlight(step)`, `show_offers(ids)`, `close()`, `is_open()`.
- Text: `scripts/ui/level_up_texts.gd` (`LevelUpTexts.TEXTS`), T-051's table keyed as there (`levelup.title`, `levelup.take`, `get_flamethrower.title/.desc`, `<id>.tier<N>.title/.desc`; 32 rows, the two `weapon.*.name` rows are not used here). Generated from the table, not retyped. T-173 added T-171's 24 cards for `get_underglow`, `get_molotov`, `get_wiper` and their `upgrade_<weapon>.tier2` to `tier8` (80 entries in all); `python game/tools/check_level_up_texts.py [task file]` checks them word for word against T-171's result-notes table (tests: `tools/test_check_level_up_texts.py`).
- Input: `_input` takes only fresh key presses (`not echo`); keys down when the screen opens are remembered (`key_down` callable, `Input.is_physical_key_pressed` by default) and ignored until released. A/D or Left/Right, Enter/KP Enter/Space.
- Look: Bangers via `Hud.comic_font()` (smoothing off), `StyleBoxFlat` with `anti_aliasing = false`, white cards with black borders, the highlighted card a thick `RING` (the combo's yellow) border with a black outline (shadow).

## Level-up screen animation (T-141)

Task T-141 (UI Agent). `scripts/ui/level_up_screen.gd` now builds the screen from T-140's art (2 screen pixels per art pixel): the cards are a `NinePatchRect` (`card_frame.png`, margin 10) inside a `Body` control that slides, the highlighted card shows its `HighlightFrame` (`highlight_frame.png`, 12 px past the card), "Take it" is a `Button` with `StyleBoxTexture` plates, the ribbon (`header_ribbon.png`, 760 x 88) holds the title label between x 152 and 608 and the emblem hangs at its left end, and `Sunburst` (`sunburst.png`, 4x, alpha 0.75, spun 1.5 degrees every 0.1 s) is behind the cards. T-051's text is unchanged. Card text wraps with `AUTOWRAP_WORD_SMART` inside a text width of 300 px, and a test checks every word of every text fits a line, so words never break mid-word.

- **Animation:** one 0.04 s frame per step, every curve one value per frame (constants `DIM_STEPS`, `SUN_STEPS`, `RIBBON_DROP`, `CARD_SLIDE`, delays `RIBBON_DELAY` 0.05, `EMBLEM_DELAY` 0.12, `CARD_DELAY` 0.2, `CARD_STAGGER` 0.1). Length `animation_length(n)`: 0.54 s for two cards, 0.64 s for three. The screen's own `_process` runs it (the screen is `PROCESS_MODE_ALWAYS`, so it plays while the run is paused); tests call `advance(delta)` and `skip_animation()`.
- **Input guard:** `is_animating()` is true until it ends. `take()` and `move_highlight()` do nothing then, `_input` uses up (and ignores) the take and move keys, and each card button ignores the mouse until the end. A key pressed during the build-up and still held at the end takes nothing until it is let go.
- **Likes bar overlap:** the screen uses only its own nodes and clock, so T-139's likes bar animation (another branch) cannot interfere; the screen sits at layer 15, above the HUD.
- **Tests:** `tests/unit/test_level_up_screen.gd` (T-052's tests now play the build-up to its end first; new ones for the art, the title's place, word-boundary wrapping, the length and finished layout, stepped and ordered frames, the spin, the input guard for keys, mouse and a held key, input after it ends, a second screen animating again, closing mid-way). Screenshots: `bash game/tools/screenshot.sh res://tests/fixtures/level_up_anim_demo.tscn out.png 12` shows the finished screen; for a moment in the build-up call Godot as `screenshot.gd` does and add `--at=<seconds>` after `--` (key frames saved in `art-archive/T-141/screenshots/`, `t_<seconds>.png`).

## Power-up overlay (T-459)

Task T-459 (UI Agent; HUD and menus, Content, "Power-up overlay"). The driving power-up gift a completed mission gives, built like the level-up screen but with its own look.

- **Choices:** `scripts/run/power_up_offers.gd` (`PowerUpOffers`, child `PowerUpOffers` of the run, `PROCESS_MODE_ALWAYS`). `bind(state)` connects `state.missions.mission_completed`, `run_started` and `level_up_choice_made`. `available_offers()` lists power-ups with `state.power_up_tier(id) < data.max_tier(id)` in power_ups.json's order; `_draw()` picks 2 at random (`rng`, tests seed it), 1 when only one is left; none: `offer_when_exhausted` "skip_gift", `gift_skipped(mission_index)`, no pause. `offers_ready(mission_index, ids)` after pausing the tree; `choose(id)` calls `state.grant_power_up(id)`, emits `offer_taken`, then opens the next waiting gift, or emits `closed` and resumes the tree unless a weapon choice waits. `offered_tier(id)`, `is_showing()`, `pending`.
- **Never at once with the level-up screen:** `LevelUpScreen.hold` (the run sets it to `power_up_offers.is_showing`) holds a weapon choice that becomes ready while the overlay is open; `show_held()` (connected to `closed`) shows it, the tree still paused. A gift for a mission completed while a weapon choice waits stays in `pending`; RunState resumes the tree right after `level_up_choice_made`, so the offers arm `_sync`, which runs on the tree's `process_frame` / `physics_frame` signals (before any node moves) and opens the gift, or pauses again if the overlay is still open (a weapon choice with nothing to offer is made at once).
- **Screen:** `scripts/ui/power_up_screen.gd` (`PowerUpScreen`, child `PowerUpScreen`, layer 15, `PROCESS_MODE_ALWAYS`). Same input as the level-up screen (A/D, arrows, Enter/Space, the card's button; a key held at opening or an echo takes nothing; nothing during the stepped build-up, 0.36 s for two cards, `is_animating()`, `skip_animation()`, `advance()`). Texts from `data/screen_texts.json`'s `power_ups` (`texts()`, `name_of()`, `describe(data, id, tier)` fills the template with the tier's numbers, `format_number` drops trailing zeros, `bounce_multiplier` = `bounce_distance_multiplier`). Cards: `{id, tier, panel, body, highlight_frame, icon, placeholder, name, desc, pips, button}`; `icon` is a `TextureRect` of power_ups.json's `icon` path when the file exists, else `placeholder` is an amber `Panel` with the name's initial (`Initial`). The header (`HazardHeader`, drawn in code) and the cards are `StyleBoxFlat` boxes; no texture art yet.
- **Pause screen:** `_choice_open()` also returns true while `run.power_up_offers.is_showing()`, so Escape does nothing over it; focus loss does nothing since the tree is paused (game_flow.gd).
- **Tests:** `tests/unit/run/test_power_up_offers.gd` (the offer rules), `tests/unit/test_power_up_screen.gd` (in the run: pause and 2 cards, texts, descriptions, tiers and pips, icon or placeholder, look, keys, mouse, held key, build-up, Escape, both waiting orders, a weapon choice with nothing to offer, new run), and `tests/unit/game/test_close_and_focus.gd` (focus loss). Screenshots: `res://tests/fixtures/power_up_screen_demo.tscn` (fresh car), `power_up_screen_next_tier.tscn` (owned tiers), `power_up_screen_weapons_gift.tscn` (the weapons gift, for comparison); `art-archive/T-459/screenshots/`.


## T-474: clickable cards

The cards have no "Take it" button. Each card carries a `click` (`GiftCardClick`, `scripts/ui/gift_card_click.gd`): a see-through `Button` laid over the whole card, so a click anywhere takes it. `GiftCardClick.attach(panel, body, frame, on_take)` builds it and is the part T-475 reuses for the driving power-up overlay. A hover tints the card's `Frame` with `GiftCardClick.HOVER_TINT` (1.35, since the shared button no longer tints, T-447); a press moves the `body` down `HudStyle.BUTTON_PRESS_DROP` pixels; the keyboard selection is still the gold `HighlightFrame`. `set_active(false)` makes it ignore the mouse during the build-up. The "levelup.take" text stays in `level_up_texts.gd`, unused. Screenshots: `art-archive/T-474/screenshots/`, from `tests/fixtures/t474_*_demo.tscn`.
