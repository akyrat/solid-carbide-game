# Tutorial slides

(Tasks T-382, T-485 and T-562, UI Agent. What the slides say and show: `docs/hud-and-menus.md`, Content, "Tutorial slides and trick list". The index is [../../README.md](../../README.md).)

## Scenes and scripts

- `scenes/menu/tutorial_slides.tscn`, script `scripts/menu/tutorial_slides.gd` (`TutorialSlides`), since T-562: six slides (the content loop, four trick slides, Survive the stream) on a 1280 x 720 stage scaled to the window. It has a left and a right arrow, six dots and a **Skip** button (jumps to the last slide; hidden on the last slide itself, T-568, since Go live starts the run; going back brings it back). The last slide has the **Go live** button (`button.start`, with the LIVE badge) and the **Don't show again** checkbox. What each slide shows: `docs/hud-and-menus.md`, Content, "The interactive slides (T-562)".
- **Practice windows (T-562):** each trick slide has a `PracticeWindow` panel (1050 x 400 at (115, 214) since T-574) holding a `SubViewportContainer` (`stretch`) and its `SubViewport`. The first time the slide shows, `_ensure_practice(i)` instances `practice_scene_path` (default `PRACTICE_SCENE`, `res://scenes/run/practice_session.tscn`, T-561's scene) into that viewport and calls `setup(<trick>)` with `TRICK_SLIDES[i][1]` (`drift`, `alt_drift`, `air_spin`, `grind`). `_apply_practice_state()` calls `set_focused(true)` and `start()` on the showing slide's session, and `set_focused(false)` and `pause()` on the others, and on all of them when the slides are hidden. Sessions are kept, so a count survives leaving the slide. The seam: when the scene doesn't exist, the window stays an empty frame (one warning) and everything else works. Duck-typed: the slide only uses `setup`, `start`, `pause`, `set_focused`, `is_completed` and the `completed` signal. `_fit()` scales each container by 1/s and sizes it s times bigger, so the viewport renders at screen pixels (the session's camera zoom follows its viewport's height).
- **Goal done: a stamp, no message (T-574; the board, 2026-11-08):** the big centred success message over the window is gone (the `tutorial.success` text stays in `data/tutorial_text.json`, unused). When the goal is done the practice session stamps a green check on its own notebook page: `PracticeSession.stamp` (`DoneStamp`, a child of the `MissionPage`), drawn in code (a double ring and a thick check in green ink, `STAMP_INK`), tilted `STAMP_TILT_DEG` (-12), `STAMP_SIZE` 92 at `STAMP_CENTRE` (118, 112) on the page, landing from 1.8x in `STAMP_TIME` (0.18 s). `restart()` clears it; `is_stamped()` tells.
- **Window and text (T-574 tweak 1):** the practice window spans the content width (1050 x 400 at (115, 214)); the instruction (and the grind's hint) sits in the game on a dark band along the window's bottom edge (`CAPTION_PAD`, `CAPTION_BAND_ALPHA`).
- `scripts/menu/clip_player.gd` (`ClipPlayer`): plays a clip from `art/tutorial/clips/<name>_sheet.png` and `<name>_sheet.json` (frame size, columns, each frame's own duration from the GIF), made by `python game/tools/gif_to_sheet.py` (test `game/tools/test_gif_to_sheet.py`). It loads when first shown and only advances while visible; `advance(delta)` is its whole clock. No longer used by the slides since T-562 (the practice windows replaced the clips); kept for the clips' own tests and tools.
- `scenes/menu/trick_list.tscn`, script `scripts/menu/trick_list.gd` (`TrickList`): the seven tricks in a grid of four columns, each an illustration with its name under it. Used by the pause screen's trick list panel (the redrawn slide 2 no longer shows it; it shows the long drift illustration in its first step).
- **Signal:** `start_pressed(dont_show_again: bool)`, sent when Start is pressed, with the checkbox state. The screen does not start the run and does not save the setting: the screen flow connects it to the main menu's Start and calls `GameSettings.save_tutorial_hidden(true)` when the flag is true.
- **Setting:** `GameSettings.load_tutorial_hidden()` / `save_tutorial_hidden(bool)`, key `hidden` in section `tutorial` of `user://settings.cfg`, false by default. `tests/unit/test_tutorial_setting.gd`.
- **Build id (T-572):** `save_tutorial_hidden` also saves `hidden_build`, the running build's id (`GameSettings.build_id()`, the trimmed text of `GameSettings.build_id_path`, default `res://build_id.txt`, which `tools/publish_itch.py` writes before the Web export and the preset's `include_filter` packs; "" when missing). With an id, `load_tutorial_hidden()` is true only when `hidden` is true and `hidden_build` equals it; with no id, `hidden` alone decides. An old save with no `hidden_build` shows the slides once in the first build with an id. Tests read `TestSave.build_id_path()` (missing by default), never the real file. `tests/unit/test_tutorial_build_id.gd`, `tests/unit/game/test_tutorial_flow.gd` (build A then build B). Screenshot fixtures: `tests/fixtures/tutorial_new_build_demo.tscn` (new build: slides) and `_same.tscn` (same build: run).

## Text

No string is written in the scripts. `TrickList.text("<dotted key>")` reads `data/tutorial_text.json` (the same lookup as the recap's); the trick names are `trick.<id>`. Headlines, labels and captions are stored in sentence case and shown in capitals (`Label.uppercase`). The arrows have no text: a triangle drawn in code, with the `arrow.left` and `arrow.right` lines as their tooltips. The checkbox's box is drawn in code too.

## Keyboard and focus (proposal for the playtest; T-562)

- **Left and Right arrow keys:** previous and next slide on every slide (they never reach a practice window: the slide's `_input` takes them). **A and D:** the same, but only on the loop slide and the last slide.
- **Trick slides:** the practice window has the keyboard as soon as its slide shows. W, A, S, D, Space and R pass through the `SubViewportContainer` to the session and the car. The arrows and Skip are set to `FOCUS_NONE` there and the focus is released, so they work by mouse only and no key (Space, Enter, Tab) presses a button. Leaving a trick slide gives them `FOCUS_ALL` back.
- **Focus on the other slides:** slide 1, the right arrow; slide 6, Go live. **Enter or Space** presses the focused control there, and **Tab / Shift+Tab** move the focus.
- **Mouse:** click the arrows, Skip, the checkbox and Go live on any slide; on the grind slide, the gift's card inside the window.
- The arrow with nowhere to go is hidden (slide 1 has no left arrow, slide 6 no right arrow). Six small squares at the bottom show the slide (the current one a long bar).

## Take tools (T-574 tweak 8, step 1 of the recorded demos; temporary, dev builds only)

- **Where they show:** on each trick slide, a row over the practice window (`take_panels`, `TakeTools`): a state label and four small buttons that take no focus. Shown only when `dev_tools_enabled` (`OS.has_feature("editor")`: run from the editor or the project folder), never in an exported game (itch), so players never see them. The button words are a dev tool's, kept in the script (`TAKE_BUTTONS`, `TAKE_STATE_TEXT`), not in the texts file.
- **Keys** (`TAKE_KEYS`, none of the car's): **F5** Reset stage, **F6** Record, **F7** Stop + save, **F9** Play take (F8 is left out: it stops a game run from the editor).
- **Practice session** (`practice_session.gd`): `reset_stage()` (count, stamp, combo, notebook and falling boxes, gift, car on the spawn standing still, tyre marks, popups, the pairs' cool-downs; stops a recording or replay), `start_recording()` (resets, takes the grind's Jump gift, then records each car step), `stop_and_save()`, `play_take()` (resets, plays the saved take on the real car with the keyboard off; `replay_drift` is the largest distance from the take's checkpoints), `take_state` and `take_state_changed`.
- **The take** (`scripts/run/practice_take.gd`, `PracticeTake`): the keys of every physics step, run-length coded (`[count, w, s, steer, held, hop]`), the board's R presses (`resets`), a checkpoint every second (place, heading, height), the start (the spawn), the gift and the count at the end. Saved as `data/tutorial_takes/<trick>.json` (the previous take kept as `<trick>.prev.json`); never in `data/levels/`. A replay drives the real car with the same keys step by step, so it follows the take exactly (the tests replay alt drift, grind and an R reset to the same place within 0.001 units).
- Tests: `tests/unit/run/test_practice_take.gd`, and the panel in `tests/unit/test_tutorial_slides.gd`.

## The recorded demo (T-574 tweak 10, step 2; the board: "minimize window effect of the video, and then have the player do it")

- **What it does:** the first time a trick slide shows (once per slide each time the tutorial opens, a proposal), if its trick has a saved take (`data/tutorial_takes/<trick>.json`, `PracticeSession.saved_take()`), the take plays in the practice window first: the real car replays the keys (`play_take`, the keyboard off, the keys pad lit as in tweak 9). When it ends, the window "minimises like a video": the session pauses on its last picture and the `PracticeWindow` panel (the caption band with it) shrinks toward a corner and fades out. Then the stage resets (`reset_stage`), the window is back at full size and the player drives. With no take, or the demo off, the slide is as before.
- **Skip:** any driving key (W, A, S, D, Space, R, by key or physical key: `DEMO_SKIP_KEYS`) skips it: the stage resets at once, with no minimise, and the car reads the keyboard (a held W drives straight on). Other keys don't skip. A key pressed while the window minimises ends the effect at once. Leaving the slide while it minimises hands over at once (the practice then pauses as any hidden slide's). A take tool (F5, F6, F9) during the demo ends the demo where it is.
- **Code:** `tutorial_slides.gd`: `demo_states` per trick slide ("", "playing", "minimising", "done"), `_maybe_start_demo`, `_on_take_state` (the session's `take_state_changed`: "played" starts the minimise), `_begin_minimise` (a tween on the frame's `scale` and `modulate:a`, the pivot on the corner, ease in), `skip_demo`, `_finish_demo`, signal `demo_finished(trick_index, skipped)`; `takes_dir_override` for tests. No new player-visible text.
- **Settings** (`data/tutorial_practice.json`): `demo_enabled` (true), `demo_minimise_seconds` (0.4), `demo_minimise_corner` (`bottom_right`; also `top_left`, `top_right`, `bottom_left`), `demo_minimise_scale` (0.1, the size it shrinks to).
- **The takes in the repo:** since 2026-11-08 afternoon all four (`drift`, `alt_drift`, `air_spin`, `grind`) are the board's own F6/F7 recordings, with the earlier takes kept as `<trick>.prev.json` (the alt drift's and grind's `.prev` are the old stand-ins). Stand-ins are marked in their `_comment` ("STAND-IN take ..."; `PracticeTake.comment`) and are made by `game/tools/make_standin_takes.gd` (the practice tests' scripted drives: the alt drift's legs, `AIR_ROUTE`, `GRIND_ROUTE` with the Jump gift and a tap then a hold). The board's F6 + F7 on a slide replaces a take (the old one kept as `<trick>.prev.json`). To make stand-ins: `"<godot>" --headless --path game -s res://tools/make_standin_takes.gd -- [--tricks=alt_drift,air_spin,grind]`; a take without the stand-in mark is left alone unless `--force`.
- **Tests:** `tests/unit/test_tutorial_demo.gd` (the settings, plays then minimises toward the corner and hands over on the spawn, once per slide, each driving key skips and resets with no minimise, other keys don't, no take = as before, demo off, leaving mid-minimise, a take tool ends it), `tests/unit/run/test_standin_takes.gd` (a take for every trick slide, the stand-ins marked, each replay does its trick and follows its checkpoints). `test_tutorial_practice_real.gd` runs with no takes (`takes_dir_override`), as before.
- **Screenshots:** `art-archive/T-574/screenshots/tweak10_demo.gif` (the alt drift stand-in playing, then the minimise and the hand-over), `tweak10_minimise.png` (six frames of the minimise), `tweak10_demo_playing.png`.
