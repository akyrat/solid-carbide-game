# Time's up screen

(The index is [../../README.md](../../README.md). What it shows and why: `docs/hud-and-menus.md`, Content, "Time's up screen"; the decision: `docs/game-loop-architecture.md`, Decisions, "Time's up screen".)

Task T-317 (UI Agent). When the 8-minute timer runs out with the kaiju alive, the run freezes at 0:00 and the time's up screen plays for 3 seconds; then the run ends with the same `run_ended("loss", coins)` as before, so whatever follows `run_ended` (the recap screen, T-320, then the main menu) follows it. A kaiju kill and a health loss (its own wreck, T-360) don't show it.

- **The hold, in `RunState` (`scripts/run/run_state.gd`):** when `advance()` takes the clock to 0 it calls `_time_up()` instead of ending at once: the result is decided there (`result` "loss", `loss_reason` "time", the recap taken, `running` false, so damage, coins, likes, tricks, kills and a kaiju kill no longer count), `timed_out` is true, `time_up_left` is `time_up_seconds`, the scene tree is paused (enemies, car, pickups and the HUD stand still) and the state alone switches to `PROCESS_MODE_ALWAYS` so its `_process` keeps counting. It sends `time_up_started(seconds)`. `advance()` then counts `time_up_left` down; at 0 `_finish_time_up()` puts the state back to `PROCESS_MODE_INHERIT`, unpauses the tree and sends `run_ended(result, coins)`. `is_timed_out()` is true in between. `start_run()` during the hold unfreezes first.
- **The 3 seconds:** `game/data/run.json`, `time_up.seconds` (3.0, the board's number), read by `RunData.time_up_seconds()` (3.0 when the section is missing). 0 ends the run at once, as before T-317 (tests may set `time_up_seconds` to 0).
- **No skipping, no pause:** the pause screen's `toggle()` does nothing while `is_timed_out()` (`_time_up_playing()`), so Escape neither opens the pause screen nor unfreezes the run. A key to skip would be cheap (a `_unhandled_input` on the screen calling a `RunState` method that finishes the hold at once); it is not built, the ticket's proposal is no skip.
- **The screen, `scripts/ui/time_up_screen.gd` (`TimeUpScreen`):** a CanvasLayer on `LAYER` 16 (over the HUD at 10 and the level-up screen at 15, under the pause screen at 20), `PROCESS_MODE_ALWAYS` so it animates while the run is paused. `GameFlow.add_run()` adds it to every game run as the child `TimeUpScreenLayer` (the main menu's run and the level creator's Play) and calls `bind(state)`: it shows on `time_up_started`, hides on `run_ended` and `run_started`. A run scene on its own (without `add_run`) still freezes for 3 s but shows no screen.
- **Text:** `load_headline()` reads `data/screen_texts.json`, `time_up.headline` (T-316), word for word; no text in the script (tested).
- **Look (placeholder in code, no PixelLab):** the COMBO BROKEN! popup's card from `ComboBrokenArt` (warning red-orange card, black border, white Bangers letters with a black outline, cracked in two halves, hard pixel edges, opaque or transparent pixels only), baked at the "normal" size (32 px font). `ComboBrokenArt.textures(text, style, in_gap := true)` puts the crack in the space between words nearest the middle (`gap_mid()`; here between "OVER," and "KAIJU") so no letter is cut away; the combo broken popup keeps its crack in the middle. Drawn as two `Sprite2D` halves with nearest filtering at a whole-pixel scale `art_scale`: the largest whole number that keeps the card within `MAX_WIDTH_SHARE` (0.9) of the screen's width, at most `MAX_SCALE` (4); 2 at the default 1152x648 window. Over a black dim.
- **Animation (a proposal for the playtest):** `pose(t)` gives the whole pose at `t` seconds, stepped to `STEP_FPS` (30) frames a second. 0 to 0.25 s the run dims to `DIM_ALPHA` (0.55) black, the HUD included. 0 to 0.18 s the headline slams in from `SLAM_FROM` (2.6) times its size, accelerating. 0.18 to 0.6 s an impact shake of `SHAKE_PX` (3 card pixels) dying away. 0.9 to 1.3 s the crack opens, easing out: the halves part by `CRACK_PART_PX` (4) each, the right one drops `CRACK_DROP_PX` (6) and tilts `RIGHT_TILT_DEG` (5 degrees), the left tilts `LEFT_TILT_DEG` (-2). Then it holds, cracked, to 3 s. `advance(seconds)` moves it on (tests); it never runs past its duration.
- **Tests:** `tests/unit/test_time_up_screen.gd` (3 s from the data; the screen starts at 0:00 and `run_ended` comes at 3 s, not at 2.9 s, with the same result and coins; about 3 s of real time while the tree is paused; frozen: the clock, damage, coins, likes, kills and a kaiju kill; 0 s ends at once; a new run unfreezes; a kaiju kill and a health loss without the screen; the headline word for word and not in the code; shown and hidden; the card's halves, pixels and scale; the pose; the crack between words; in the game: enemies, car and pickups frozen, Escape ignored, no recap before 3 s, then the recap with the time's up title, the coins banked, and Continue to the main menu). Tests that ran the clock out and expected an instant end now let the 3 s play (`test_run_state.gd`, `test_wreck.gd`, `game/test_screen_flow.gd`, `level_creator/test_play_level.gd`).
- **Screenshot and GIF:** `bash game/tools/record_time_up.sh [out_dir]` with the fixture `tests/fixtures/time_up_demo.tscn` (a run from the main menu, the car driving among minions, the clock set to 0:01 at 1 s); result in `art-archive/T-317/screenshots/` (`time_up.png`, 1.5 s into the screen; `time_up.gif`, from just before 0:00 through the whole 3 s to the recap).
