**The HUD's shared style (task T-428, goal G-008 "A consistent HUD"; HUD and menus, Decisions):** every font, font size, font colour, outline colour and width and panel colour the HUD, the pause screen and the level-up screen use lives in one place, `scripts/hud/hud_style.gd` (`HudStyle`, a static script with no other HUD dependency). How the scripts read it:
- **Labels** take a named role: `HudStyle.apply(control, "<role>"[, colour])` sets the role's font (`"comic"` = `HudStyle.comic_font()`, Bangers without smoothing; `""` = the theme's default; the old `"clock"` system font is gone since T-429), `font_size`, `font_color` (all four button states on a Button), `font_outline_color`, `outline_size` and, with `caps`, a Label's `uppercase` (T-429; Bangers draws a Button's lowercase as capitals anyway) from `HudStyle.LABELS`. Roles: `coins`, `clock_digits`, `sub_goal`, `weapon_count`, `air_counter` (airtime and drift), `viewers_number`, `viewers_unit`, `viewers_flight`, `viewers_drop`, `pause_title`, `pause_text`, `level_up_title`, `level_up_card_title`, `level_up_card_desc`, `level_up_button`. A key left out of a role is set by the script as it changes (the clock's colour per time step from `data/hud.json`; the viewers number's size per heat step). The optional colour replaces the role's (the viewers colours, which `hud.json` can set).
- **Heat looks** (`HudStyle.HEAT_STEPS`, the old `ComboHeat.STEPS`): `HudStyle.apply_heat(label, step, ...)` sets a step's size, colour, outline and glow ring; `HudStyle.glow_color(step, pick)` gives the flicker colour. The viewers counter passes its own sizes, base colour and half glow and keeps its role's outline.
- **Drawn pieces** read constants: `FIRE_PALETTE` (the sub goal's flames), `SUB_GOAL_GLOW`, `HEALTH_COLOR`/`HEALTH_TOP_COLOR` (the sub goal's fill), the HUD art (T-429): `HUD_ART_SCALE` 2, `CLOCK_PANEL_ART` with `clock_panel_box()` (a StyleBoxTexture, content margin `CLOCK_PANEL_CONTENT_MARGIN` 3), `CLOCK_DIGIT_ART`, `CLOCK_DIGIT_FRAME` and `CLOCK_DIGIT_OFF_SHADE`, `WEAPON_ICON_ART`/`WEAPON_ICON_FRAME`/`WEAPON_ICON_ORDER` with `weapon_icon(id)` (an AtlasTexture frame, or null), `POPUP_PALETTE` and `POPUP_TEXT` (the trick popups' baked colours and lettering sizes; the popups bake from their own copy, `HudStyle.new_comic_font()`), `BROKEN_PALETTE` (the combo broken popup), `KAIJU_*` (the kaiju's bar), `PAUSE_*` (the pause strip, dim, controls and trick list size), `LEVEL_UP_*` (the level-up dim, title colours and sizes, hover tint).
- The scripts' old constant names (`Hud.LABEL_COLOR`, `ComboHeat.STEPS`, `LikesFire.PALETTE`, `TrickPopupArt.PALETTE`, `WeaponIcons.COUNT_FONT_SIZE`, `LevelUpScreen.TITLE_SIZE`, the pause screen's `STRIP_COLOR`, ...) are kept and point at `HudStyle`, so a value is changed in `hud_style.gd` only. `Hud.comic_font()` returns `HudStyle.comic_font()`.
- **The HUD style sheet's values (task T-429, Visual style, Decisions, "The HUD style sheet"; proposals for the playtest):** words are Bangers everywhere, outline colour `OUTLINE_COLOR` (8, 8, 15), outline 6 for words and 8 for big numbers. **The HUD scales with the window (task T-431, goal G-008; HUD and menus, Content, "The HUD scales with the window"):** `Hud` builds `root` ("Scaled", a Control, the Hud's first child) and puts every HUD piece in it: the reactions, the clock, the hearts and weapon icons (`Left`), `Bottom`, the sub goal, the coins, the viewers counter and the airtime and drift counters (`LikesSpring` and `ComboHeat`, plain Nodes, stay on the Hud). The pieces keep their layout page places (1152 x 648, `Hud.LAYOUT_SIZE`) and anchors, measured against the root. `_layout_root()` (at `_ready` and on every `size_changed`) sets `root.scale` to `Hud.scale_for(view, hud_size)` = min(width / 1152, height / 648) x `hud_size` / 100 and `root.size` to the window over that scale, so each piece keeps its corner or edge and a size in proportion to the window (the height decides on a wide screen, the width on a narrow one). `root.texture_filter` is nearest and every piece inherits or sets nearest, so the pixel art stays hard-edged at the fractional scales (1.667 at 1920 x 1080, 2.222 at 1440 high). The world camera is never touched. `set_hud_size(percent)` (clamped to `GameSettings.MIN_HUD_SIZE`..`MAX_HUD_SIZE`) rescales at once; `hud_scale()` reads the scale; `to_layout(screen_point)` turns a screen point into the root's pixels (the sub goal's burst and the crash's bad burst use it). `ViewersFlight` is top level (screen pixels), so `fly_in` gives it `base_scale` = the counter's scale, which also scales its arc. Above 100 the layout page is shorter than 648, so `SubGoal.keep_above()` moves the square up just enough to stay `MARGIN` (16) above the viewers counter (at 100 it never moves). Tests: `tests/unit/hud/test_hud_scaling.gd` (the five window sizes 1152 x 648, 1920 x 1080, 2560 x 1440, 3440 x 1440 and 960 x 540, both slider ends, resize, nearest filtering, the camera's zoom, bursts and flights); the older layout tests measure in layout page pixels times `hud_scale()`. Screenshots: `tests/fixtures/t431_hud_*.tscn` and `t431_slider_*.tscn` (script `t431_hud_scale_demo.gd`, a SubViewport of the size, saved to `art-archive/T-431/screenshots/`): `bash game/tools/screenshot.sh res://tests/fixtures/t431_hud_3440x1440.tscn screenshots/root.png 80`.

**Every screen scales with the window (task T-494; HUD and menus, Content, "The HUD scales with the window"):** one helper, `UiScale` (`scripts/ui/ui_scale.gd`). `UiScale.fit(view, base = UiScale.BASE)` = max(min(view.x / base.x, view.y / base.y), 0.01); `UiScale.BASE` is 1152 x 648 and `Hud.LAYOUT_SIZE` is that constant, and `Hud.scale_for` is `UiScale.fit` times the HUD size. `UiScale.keep(control)` scales a screen's root Control: anchors to the top left, `scale` = the fit, `size` = the window (or the parent Control's size, when the screen sits in one) over the scale, `texture_filter` nearest. It refits when the root enters the tree, on the viewport's `size_changed` and, as a catch-all, on any `process_frame` where the window's size differs from the one it last fitted (the headless test window and some embedded windows don't send `size_changed`); the connections live on a small keeper object in the Control's metadata, so they go with the Control. Users: `MainMenu` (itself), `RecapScreen` (itself), and the `_root` of `PauseScreen` (with its trick list panel and `HudLayoutEditor`), `LevelUpScreen` and `PowerUpScreen`. `TutorialSlides._fit` (its 1280 x 720 stage) and `GarageScreen.fit` (its column's natural size) use `UiScale.fit` with their own base. `HudLayoutEditor` works in screen pixels (the HUD's pieces), so it turns its own pointer positions into screen points (`_to_screen`) and draws the frames back in its own pixels. Tests: `tests/unit/test_ui_scale.gd` (the scale at 1152 x 648, 1280 x 720, 1920 x 1080, 3840 x 2160 and 3440 x 1440, filling the window, following a resize, and that each screen uses it). The headless test window is 64 x 64, so tests that measure a scaled screen's layout in pixels set the window to 1152 x 648 first (`test_pause_screen.gd`, `test_pause_camera_controls.gd`, as `test_power_up_screen.gd` already did). The scaling scan (`screen_gallery.py --sizes`) checks it on the real screens; T-494's before and after reports are in `art-archive/T-494/`.

**The HUD layout (task T-453; HUD and menus, Content, "The HUD layout editor"):** `scripts/hud/hud_layout.gd` (`HudLayout`, no nodes) holds the movable pieces' ids (`PIECES`: hearts, weapon_icons, coins, clock, sub_goal, viewers) and the maths: a moved piece is an entry `{ax, ay, dx, dy}` in layout pixels, its anchor (0, 0.5 or 1 per axis, `anchor_for()`, by the third its centre is in) and its distance from it; `position_for()` gives `a * (area - size) + d`, clamped fully inside the root (`clamp_inside()`); `snap()` puts a dragged place on the `GRID` (4) and at `EDGE_MARGIN` (16) when within `EDGE_SNAP` (12) of an edge; `clean()` drops invalid entries. On the Hud: `piece(id)`, `piece_rect(id)` (the piece's shown rect in the root's pixels; the sub goal's includes its label row), `layout` (the entries), `set_layout()`, `move_piece(id, layout_pos)` (snaps, stores the entry, places it), `reset_layout()`. `_apply_layout()` runs from `_layout_root()` (every resize and HUD size change): a moved piece gets `position` set from its entry (its own anchors untouched), a default one gets its remembered `offset_left`/`offset_top` back (`_default_offsets`, taken at `_ready`), and `SubGoal.keep_above()` runs only while the sub goal and the viewers counter are both at their defaults. A moved piece that grows (`resized`, the sub goal's label row too) is placed again so it stays on screen. The gift arrows' `hud_rects()` merge the sub goal's label row into its rect, so the arrows keep clear of it wherever it is. Saved by `GameSettings.save_hud_layout()`/`load_hud_layout()` (section `hud_layout`). Tests: `tests/unit/hud/test_hud_layout_editor.gd`; `tests/unit/run/test_gift_drops.gd`, `test_t453_arrows_stay_clear_of_moved_hud_pieces`.

## The text layout capture (T-524)

The data for the board's text editor page (every in-game text on its real screen, new words typed and drawn in place). One command, run from the repo root with `GODOT_BIN` set (needs a real window, about 15 seconds):

`python game/tools/screen_gallery.py --text-layout --out screenshots/text-editor` (output git-ignored, outside `game/`).

It is the screen gallery (T-479: `screen_gallery.py`, `screen_gallery.gd`) with `--text-layout`, plus `text_layout.gd` (Godot half) and `text_layout.py` (Python half, standard library only); tests `game/tools/test_text_layout.py`. The gallery's own screens are unchanged; with the flag it also reaches extra states: tutorial slide 4, the combo multiplier beside the car, the multiplier loss, the heal popup, and the God mode entry and page (25 screens).

Output folder:
- `<screen>.png` and `<screen>_blank.png`, both 1280 x 720. The pair is taken in the same frame with `Engine.time_scale` at 0, so animation does not move between them. The blank hides the text without moving anything: a Label or RichTextLabel gets `self_modulate` alpha 0 (a transparent colour override when it has a background of its own), a Button or LineEdit gets its text and outline colours made transparent (icons stay), a baked popup, the time's up card and the clock's art digits are hidden whole. Each screen records `text_nodes_still_showing_in_blank` (0 expected) and `pixels_changed_outside_text` (pixels that differ away from every text rect; non-zero only for things that animate on real time, such as the tutorial clips and the helicopter).
- `text_layout.json`: `screens`, `rows`, `templates`, `fonts`, `not_capturable`, `coverage` (the tool's docstring, `text_layout.py`, lists every row field). A row is one visible text node, with the rect in screenshot pixels (the axis-aligned box after scaling and rotation; `scale` and `rotation_deg` too), the font as Godot resolves it (theme overrides, `LabelSettings` and the theme default; `font` is the repo path, `font_file` the copy in `fonts/`, `font_size` the size and `font_px` the size in screenshot pixels), colour, outline, shadow, alignment, wrap, uppercase, line spacing, max lines, overrun, clip, the style box padding, and the text inventory match (`inventory`: source, key, screen). Kinds: `control` (a Label, RichTextLabel, Button, CheckBox or LineEdit), `baked_popup` (a trick popup: the text is part of a baked bubble picture; `rect` is the plain bubble the text sits in, `art_rect` the whole picture with rings and flames), `baked_card` (the time's up headline) and `art_digits` (the clock). The page can restyle and move a `control` row; baked kinds need the art baked again, so they are also listed in `not_capturable`.
- Templates: a node many texts render into (`level_up_weapon_card_title`, `level_up_weapon_card_description`, `power_up_card_name`, `power_up_card_description`, `missions_note_line`, `trick_popup`, `recap_*`, `trick_list_row`) carries `template` and `template_keys` (every inventory key that renders there, with its text). The rule table is `TEMPLATES` in `text_layout.py`.
- `fonts/`: every font file the rows use. Godot's built-in default font (Open Sans SemiBold, used by the garage, menus and cards that set no font) is not a file of the game; it is written out of the engine into `fonts/`.
- `not_capturable`: text not drawn by a Control: the tutorial clips' key pad letters (`draw_string`, `key_pad.gd`), and the baked rows above. Text baked into a plain art PNG (for example a logo) cannot be detected and is not listed.
- `coverage`: text inventory rows (text_files and code) matched to a node or a template, and the unmatched ones with a reason (not in the game yet, unused, a tooltip, or no captured screen shows it). A node's text matches a row when it equals the row's text, `{placeholders}` and `%d` standing for any text (case ignored as a second try). The command fails when under 80% of the text_files rows are matched.
