## Level creator (T-231)

The level creator (Level design, Decisions, "Level creator") builds levels in the map-file format of `data/level/elevation_sample_map.json` (`map`, `legend`, `ground_rows`, `buildings`, `pattern_copies` with the boulders, `platforms`, `ramps`), so the run, `GroundHeight` and the enemies' pathfinding read them unchanged. Later creator tickets fill in the rest of this section.

- **Where levels are saved (a proposal for the board):** `game/data/levels/`, read as `res://data/levels/` (`LevelStore.LEVELS_DIR`). The creator runs from the repo and is never exported.
- **Storage:** `scripts/level/level_store.gd` (`LevelStore`): `list_levels(dir = LEVELS_DIR)` gives `[{name, path}]` sorted by name (the file's `name`, or its file name), `load_level(path)` the level as a Dictionary (empty when missing or not a JSON object), `save_level(path, data)` writes indented JSON, creating the folder, and returns `OK` or an error. Tests: `tests/unit/test_level_store.gd` (only under `RunPaths`, never the real folder).
- **Validator:** from the repo root, `python game/tools/check_level.py <file.json>` prints `OK` (exit 0) or one line per problem (exit 1). It runs `check_height_data.py` on the file and also checks that every building, rooftop, ramp and boulder lies inside `map.rect`, that the edges of buildings, rooftops and ramps lie on even units (`enemy_navigation.gd`'s `CELL` = 2), and that `ground_rows` has as many rows and columns as the map's size in tiles (1 tile = 1 unit); since T-272 also that every pair of obstacles (`pairs`) names two existing obstacles, and since T-394 that no two pairs name the same two obstacles (an obstacle can be in several pairs; "Thread the needle (T-272)" in level-creator-pieces.md). Tests: `tools/test_check_level.py`.
- **Opening the creator (T-234):** a separate app with its own main scene, `scenes/level_creator/level_creator.tscn`; the game's main scene in `project.godot` stays the game, and no game menu or script refers to the creator. From the repo root: `bash game/tools/level_creator.sh`, or `powershell -ExecutionPolicy Bypass -File game/tools/level_creator.ps1`. It opens on the level list (`scripts/level_creator/level_list_screen.gd`): each level from `LevelStore.list_levels()` by name with Play and Edit, and the New level button (the only thing there when there are no levels). New level and Edit open the editor scene (`scenes/level_creator/editor.tscn`, an empty map or the level loaded; "The editor (T-235)" below); Play starts a run on the level ("Playing a level (T-239)" below). Every label comes from `data/level/creator_texts.json` through `CreatorTexts.get_text(key)`; `tests/unit/level_creator/test_creator_texts_only.gd` fails on any hard-coded label in the creator's scripts and scenes. Tests: `tests/unit/level_creator/`. Screenshots: `art-archive/T-234/screenshots/`.
- **Playing a level (T-239):** on the level list, press **Play** on a level's row. The creator (`scripts/level_creator/level_creator.gd`, `play_level(path)`) swaps the list for a full run on that level's file: the game's own run (8:00 on the clock, the minions, the kaiju at boss time, weapons, level-ups, the pause screen on Escape), built by `GameFlow.add_run(parent, progress, layout_path)`, the same function the main menu's Start uses, so the garage upgrades from the saved progress, the saved zoom and camera options apply, and the run's coins are banked into the save as in the game. The run's `layout_path` is the level's file (T-230), so the map, its rooftops and ramps, and the enemies' navigation are all built from the level. **Where the run returns (a proposal for the board):** when the run ends, win or loss, the creator shows its level list again (no message), and Play can start the level again. The game's own flow is unchanged: Start on the main menu still plays `data/level/elevation_sample_map.json`. Signals: `play_requested(path)` just before the run starts, `run_shown` after it, `list_shown` whenever the list is on screen. Tests: `tests/unit/level_creator/test_play_level.gd` (a level saved into a temporary folder, `RunPaths`). Screenshots (`bash game/tools/screenshot.sh res://tests/fixtures/level_creator_play_demo.tscn art-archive/T-239/screenshots/run_on_custom_level.png 150`, and `level_creator_play_demo_ended.tscn` for the list the run returns to; `level_creator_play_demo_list.tscn` stops on the list before Play): `art-archive/T-239/screenshots/`.

  - **The spawn point (T-280):** (Level design, Decisions, "The car's spawn point"; labels T-279's; the numbers and looks are proposals). Every level has exactly one, where its run starts the car.
    - **Data (one place, `scripts/level/level_spawn.gd`, `LevelSpawn`):** the level file's `spawn` is `{x, y, heading}`: the middle of a 2 x 2 unit cell (units) and a heading in degrees, the car model's rotation (0 faces +x, 270 faces -y, the run's own start), one of eight (`HEADING_STEP` 45).   - **Snapping (T-237):** `scripts/level_creator/snapping.gd` (`LevelSnapping.placement`) decides where a piece goes; the editor's preview and blue outline show that place before the click. **Tile grid:** the piece's top-left corner goes on the corner of the 2 x 2 unit cell under the cursor, so every edge of a building, rooftop and ramp lies on even units (`enemy_navigation.gd`'s `CELL` = 2, which `check_level.py` checks). **Snap distance (a proposal for the board): `SNAP_DISTANCE` = 4 units** (two cells). **Close neighbours:** a building, rooftop or ramp whose edge is within the snap distance of a placed building's, rooftop's or ramp's edge (and, for a building, a road tile's), with the two side by side (their gap the other way within the snap distance too), moves so that edge lies on the neighbour's: flush against it (a building against a road or another building) or lined up with it (a 6 along its 3's edges). Each axis moves to its closest such edge. **Ramps:** a ramp whose top end is within the snap distance of the side it climbs (from its view) of a rooftop at its top height goes onto that side, slid along it to lie within it, and is linked to that rooftop; this wins over the neighbour snap.   - **Painted roads in the run (T-391):** (Level design, Decisions, "Roads painted in the creator show in the run"). **The cause:** the run's map (`mvp_map.gd` `_ready`) always loaded the game's own ground, `data/level/mvp_ground.json`, and never read the level file's `ground`; only the editor turned that into a ground layout (`LevelDocument.ground_layout`). So every painted road, junction and crossing showed in the editor and was missing in the run (the game's streets were drawn there instead). **The fix:** one place builds the layout from a level's ground, `scripts/level/level_ground.gd` (`LevelGround`: `layout_of(level)` from the file's `ground` tiles and cells, `layout_from_ids(rows, origin)`, `values()` catalogue id -> atlas index or `EXTRA_BASE + k` for the `extra` textures). It lives under `scripts/level/` because the run uses it and the creator's scripts are left out of an export. `mvp_map.gd` draws `LevelGround.layout_of(layout)` when the layout has a creator ground and falls back to `GROUND_PATH` otherwise (the game's own map, a file without `ground`); `LevelDocument.ground_layout()` calls `LevelGround.layout_from_ids`, so the editor and the run draw the same layout. Levels saved with the creator's ground now play with their own ground (an all-gravel level is gravel in the run).
