## Description

The board wants a human-readable overview of the agent team. The Project Lead does this task itself, because it is documentation and agent descriptions, which the Project Lead maintains. It changes no agent definition and no game files.

Board decisions for this task (2026-10-04):
- The diagrams show the agents' **working copies** of their relationships (`agent-notes/<agent>.md`), not the originals in the agent definitions, because the working copies reflect how agents actually work.
- **Two diagrams:** one for hand-offs (who sends work to whom, and what), one for collaborations.
- The diagrams are **generated by a script** from the working copies, so they cannot drift from them. The prose is written by hand.
- The MVP is the game described in the **Final GDD** (`docs/short-gdd/Solid_Carbide_-_Final_GDD.pdf`), including the feature limits it sets.

### 1. "Agent Crew" section in the root README

Add an "Agent Crew" section to `README.md`: every role on the team (the Project Lead and the 10 agents in `.claude/agents/`), each with a one-line description of its role, and a link to `agent-notes/agents-interactions.md`. Descriptions say what the role does, not game details.

### 2. `agent-notes/agents-interactions.md`

This file is the shared overview; the other files in `agent-notes/` stay each agent's own working copy. It has three sections:

1. **How the agents connect:** the two Mermaid diagrams, generated by the script (see 3). Every role is a node, and the board appears as a node too. Edge labels are short (a few words); the full relationship text goes in a generated table under each diagram. A line above the diagrams says they are generated from the working copies, how to regenerate them, and that the originals in the agent definitions may differ.
2. **What each agent produces for Solid Carbide:** one short entry per role, saying what it delivers to the project (code, data, art, sound, documents, checks). Game details are not repeated: each entry points to the document that holds them.
3. **Why this crew is needed for the MVP:** a short summary of why this set of agents is needed to build the MVP as the Final GDD describes it, mapping the GDD's main parts to the agents that build them and respecting the GDD's feature limits. It states plainly that the quality of the output depends entirely on how well the game is defined in the documents, and names which documents are still empty or thin today.

### 3. Diagram generator script

Write `tools/generate_agent_diagrams.py` (project tooling at the repo root, not game code; Python standard library only):
- It reads every working copy in `agent-notes/` (skipping `agents-interactions.md`) and parses the "Gets work from", "Hands work to" and "Collaborates with" lists.
- A hand-off that appears on both sides (A "hands work to" B, and B "gets work from" A) is drawn once.
- A collaboration listed by both agents is drawn once.
- It tolerates working copies that change shape over time (new sections, missing lists, notes from experience) without failing. It reports any entry it cannot match to a known role instead of dropping it silently.
- It rewrites only the part of `agents-interactions.md` between two marker comments, leaving the hand-written sections untouched.
- `--check` mode exits non-zero if the file is out of date, without changing it.
- Write tests for the parsing, de-duplication and marker replacement, and run them.

Document the script's usage in the "How the agents connect" section of `agents-interactions.md`.
